# SP1 방어구 파츠 실측 규격 — 애니메이션 대응 여부

## 결론: 된다. 무기와 같은 방식이다.

리그의 방어구 슬롯은 전부 **뼈 하나에 통째로 붙은 단일 스프라이트**다.
메시 변형(스키닝)을 하지 않으므로, 규격만 맞추면 AI로 만든 PNG도 그대로 붙고
애니메이션은 뼈가 알아서 움직여 준다.

### 근거 (실측)

| 확인 | 결과 |
|---|---|
| 컴포넌트 | 모든 슬롯 = `SpriteRenderer` + `SpriteResolver` + `SpriteSkin` |
| SpriteSkin 본 수 | 방어구 **1개**, 무기 **0개** → 변형 없음, 강체 부착 |
| 피벗 | 39종 전부 **0.50, 0.50** |
| PPU | 100 |

**실제로 꽂아 봤다.** 갑옷 슬롯의 SpriteRenderer 에 뼈 정보가 전혀 없는 평범한
PNG(`WearParts/w_wood_sword`)를 넣었더니 `isVisible=True`, 다음 프레임에도 유지되고
화면에 그려졌다. SpriteSkin 이 거부하지 않는다.

## 만들 때 지켜야 할 것

1. **전신 옷을 한 장으로 그리면 안 된다.** 갑옷은 60×47짜리 몸통 조각이고
   어깨·목·허리가 따로 있다. 도포 한 벌을 원하면 조각으로 나눠 그려야 한다.
2. 방향을 통일한다 — 투구는 **왼쪽을 본다**.
3. 크기가 27~78px로 아주 작다. 디테일을 넣어도 안 보인다. 실루엣으로 승부한다.
4. 화풍은 무기와 같다: 두꺼운 순검정 외곽선, 재질당 2~3톤 플랫 셀 셰이딩,
   저채도 팔레트 (`tools/sp1-wear-reference.md` 참고).
5. 피벗은 정중앙. 그림의 무게중심이 캔버스 중앙에 오게 타이트 크롭 후 배치한다
   (`tools/fit_wear.py` 가 하는 일과 동일).

## 시범 결과 — 투구 6종 (2026-08-14)

`sheet_armor_hat` 한 장으로 무협 두건·삿갓·유건·도관 6종을 뽑아 리그에 넣고
게임까지 확인했다. 파이프라인은 무기와 완전히 동일하게 돌아간다.

배운 것: **눈으로 크기를 판단하면 틀린다.** 처음 170px로 뽑았을 때 "너무 크고
얼굴을 덮는다"고 봤는데, 원본과 화면에서 실측해 보니 높이·위치는 정확히 같고
**가로만 1.18배**였다. 145px로 줄이니 가로 배율 1.00이 됐다.

측정 방법 (재현용):
1. `EditorApplication.isPaused = true` — 다른 게 안 움직이게 정지
2. `ChangeSlotItem(slot, "0000")` → 스크린샷 (기준선)
3. 원본 인덱스 → 스크린샷, 우리 인덱스 → 스크린샷
4. 기준선과 차분(diff)해 각각의 bbox 를 구해 비교

정지하지 않으면 몹·재화 숫자가 바뀌어 diff 가 화면 전체로 번진다(실제로 겪음).

| | 화면 크기 | 가로배율 | 윗변차 |
|---|---|---|---|
| 원본 0019 (투구) | 245×241 | — | — |
| 우리 t2 (두건) | 245×205 | 1.00 | +18 |
| 우리 t6 (도관) | 246×199 | 1.00 | +20 |

## 파츠가 없는 슬롯 (Pants / ArmorArm)

슬롯 자체는 리그에 있으므로, 무기에 9000번대를 새로 넣었던 것과 같은 방법으로
`WuxiaPartInstaller` 로 라벨을 추가하면 된다. 다만 **원본 참고 대상이 없어서**
크기·위치를 눈으로 맞춰야 한다 — 다른 슬롯보다 시행착오가 든다.
