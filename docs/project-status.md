## 3. 목표

### 3.1 게임 목표

**"자동 사냥이어도 구경하는 맛이 있는"** 방치형. 이를 위해 세 가지를 만족해야 한다.

1. **물량감** — 한 화면에 6~11마리, 맵 전체로는 최대 34마리. 쓸어버리는 그림.
2. **성장 실감** — 레벨업 필요 처치 수를 전 구간 300~800으로 유지(무한정 늘어나지 않음).
3. **세력별 개성** — 정파·사파·마도가 각각 다른 색·리듬의 무공을 쓴다.

### 3.2 출시 목표

- 안드로이드(구글 플레이) 우선. AAB 빌드 파이프라인은 구축됨.
- 확률형 아이템 **확률 공시** 화면 구현 완료 (스토어 심사 요건).
- 남은 필수: 키스토어 서명, BGM 선정, 실기기 테스트, 콘솔 등록 → **유저 작업 영역**.

## 4. 개발 진행 상황

### 4.1 성장 · 난이도 · 보상 (G 시리즈) — 완료

곡선 자체가 망가져 있었다. 적 HP는 100스테이지 동안 3,259배 오르는데 킬당 경험치는
20.8배만 오르고 레벨업 비용은 6,600배 올라, **레벨업에 12만 킬이 필요한 구간**이 있었다.

| 항목 | 결과 |
|---|---|
| 레벨 상한 | **200** (1~100은 레벨, 100 이후는 경지·환생이 주 성장축) |
| 스테이지 | **200개 / 20챕터** (10스테이지마다 보스) |
| 레벨업 필요 킬 | 1~100 구간 약 300 → 200레벨 약 821 |
| 경지 | 8단계, 요구 레벨 1/15/35/60/90/120/155/195 |
| 환생 | 최소 스테이지 115, 배수 지수화 |
| 던전 | 난이도 3단계(하/중/상), 전투력 게이트 + 보상 배수 |
| 레이드 | 난이도 3단계, 주간 입장권 3장, 난이도별 적 공격력 배수 적용 |

생성기: `tools/gen_level_xp.py`, `tools/gen_stage_table.py`, 검증기 `tools/sim_growth.py`.

**수정한 실제 버그 2건**
- 레벨 60 이후 경험치 표 외삽이 10,000부터 다시 시작해 **비용이 30배 폭락**했다.
- 킬당 경험치가 스테이지 성장률과 분리돼 **경험치 공급이 고갈**됐다.

### 4.2 콘텐츠 완결성 (H 시리즈) — 완료

| 단계 | 내용 |
|---|---|
| H1 | 적 방어력 도입 — 방어 관통 스탯이 그전까진 무의미했다 |
| H2 | 스폰 수·젠딜레이 데이터화 (18마리/0.7초 → 34마리/0.3초) |
| H3 | 사망 처리 — 5초 운기조식, 3연속 사망 시 한 단계 강등 (자원 손실 없음) |
| H4 | mapTier를 실제 난이도로 (스탯·보상 배수) |
| H5 | 확률 공시 화면 — 소환/드랍/강화/스타포스/감정 확률을 **상수에서 직접 읽어** 표시 |
| H6 | 무기 세트 효과 (2/4/6종 보유 시 +3/5/8%) |
| H8 | 대형 맵 + 물량 + 세력별 스킬 이펙트 |
| H9 | 테마별 발판 배치 |

#### H8 — 대형 맵과 세력 이펙트

- 맵 폭 = 화면의 **3배**(`MapWidthFactor`). `FieldWorldStage.ScrollX`로 히어로를 따라가고
  배경은 0.35 비율로 시차 이동. 21마리 교전 시 **209fps**.
- 세력색: 정파 청광 / 사파 독록 / 마도 혈홍 — 모든 스킬·타격·기운에 적용.
- **세력 절기**(25처치마다): 정파 검강참(5연참) / 사파 암기난무(7연타) / 마도 혈마파(3연 대폭발).

**수정한 실제 버그**: 필드 좌표는 y를 **바닥 기준**으로 재는데 UI는 **중심 기준**이라,
모든 타격 이펙트와 데미지 숫자가 액터보다 약 490px 위에 떠 있었다. 오래된 버그였다.

#### H9 — 테마별 발판 (`MapLayout.cs`)

층 수를 3 → **4**로 늘리고, 층마다 화면을 덮던 막대 하나를 **여러 칸(세그먼트)으로 쪼갰다.**

| 테마 | 챕터 | 배치 원형 |
|---|---|---|
| 죽림 | 1~4 | 산개형 — 크기 제각각 발판이 어긋나게 흩어짐 |
| 설산 | 5~8 | 양끝절벽 — 좌우 대지 + 중앙 다리 + 돌기둥 |
| 석굴 | 9~12 | 규칙층 — 폭이 같은 얇은 선반 반복 |
| 유적 | 13~16 | 계단유적 — 위로 갈수록 좁아지는 대칭 계단 |
| 마교 | 17~20 | 2단대공간 — 천장·지면 두 덩어리 + 징검다리 |

- 좌표는 맵 절반폭 비율(-1~1)이라 해상도·맵폭이 바뀌어도 그대로 쓴다.
- 같은 테마 안에서 챕터가 깊어질수록 발판이 밀리고 좁아진다(심처 변형).
- 발판이 없는 층엔 몹도 안 나온다 → 테마마다 실제 쓰는 층 수가 다르다.
- 몹은 자기 발판 밖으로 못 나가고, 히어로는 발판 끝을 지나면 지면으로 떨어진다.

**수정한 실제 버그**: 배경·발판은 `StageIndex`(돌파 단계)를, 몹 배치는 `HuntStage`(사냥 단계)를
보고 있어 두 값이 다른 구간에서 몹이 발판 밖 허공에 섰다. `ActiveStageIndex()`로 통일.

### 4.3 전투 연출 — 완료

부드러운 60fps 보간이 오히려 **가벼워 보이는** 문제가 있었다. 2D 도트 UI와 섞이면 3D 티가 난다.

- Animator를 **꺼 두고**(`enabled = false`) 정해진 간격으로만 민다. `RigFps = 8`.
  위치는 매 프레임 갱신되므로 **이동은 부드럽고 자세만 끊긴다** — 2D 액션의 그 느낌.
- 공격 클립만 `AttackAnimSpeed = 1.9`배로 흘려 0.67초 스윙을 0.35초로 접는다 → **3프레임**.
- 타격 판정·이펙트를 `ImpactDelay`(= 1/RigFps = 0.125초)만큼 미뤄 **칼이 닿는 프레임**에 터뜨린다.
- 리그에 점프 클립이 없어 **Crouch(도약) → Run(체공) → 복귀**로 점프를 만들었다.

> `animator.speed = 0`으로는 안 된다. speed는 배율이라 수동 Update를 불러도 아무것도 안 흐른다.

### 4.4 UI — 대부분 완료

캐릭터창(`win_paper`)이 디자인 기준이다. **통짜 한지 한 장 + 이중 먹선 칸 + 구름 현판.**

처음엔 부품(한지 + 먹선 9-slice)으로 조립했으나, 늘릴수록 선 굵기가 무너져
"A4에 대충 그린 것"이 됐다. → **창마다 통짜 시트를 굽고, 그림을 실측해 코드를 맞추는** 방식으로 전환.

| 시트 | 크기 | 쓰는 창 |
|---|---|---|
| `win_paper` | 1600×896 | 캐릭터 |
| `win_kit_grid` | 1360×1008 | 장비 · 스킬 (본창) |
| `win_kit_side` | 560×1008 | 장비 · 스킬 (좌측) |
| `win_kit_slots10` | 1360×1008 | 동료 (5×2) |
| `win_kit_cards6` | 1360×1008 | 상점 (3×2) |
| `win_kit_list` | 1360×1008 | 목록(문파·순위·정보) |
| `win_kit_reward` | 1008×768 | 오프라인 보상 |

연출은 `WuxUiFx` — 두루마리 펼침(0.2초) + 보상 반짝임(기존 전투 FX `HitBurst` 재사용).
창이 열릴 때 `InkifyPaperText`가 한지 위 밝은 글씨를 자동으로 먹빛으로 돌린다.

**수정한 실제 버그**: 통짜 아트가 **버튼을 그림으로만 그려 놓은 곳**이 있었다.
오프라인 보상창의 '2배 받기'는 버튼이 아예 없어 눌러도 아무 일도 일어나지 않았다.

**남은 잔손질 2건**
- 장비창 격자 오른쪽 여백 + 격자 아래 글씨 찌꺼기
- 설정창 버튼이 구매 에셋 검은 돌 그대로 (판때기만 한지로 교체된 상태)

## 5. 로컬 AI 아트 개발 방법

### 5.1 구성

```
tools/imggen/
  server.py        # HTTP 서버 (포트 8009)
  .venv/           # 전용 파이썬 환경
  hf/              # 모델 캐시 (~19GB, H 드라이브 — C를 채우지 않는다)
```

- 모델: **Z-Image-Turbo** (Tongyi-MAI, Apache 2.0) — 로컬 CUDA, bf16
- 기본 파라미터: `steps=9`, `guidance_scale=1.0`
- API: `POST http://127.0.0.1:8009/generate` → `{"prompt","width","height","seed"}` → PNG

### 5.2 기동

```powershell
Start-Process -FilePath "H:\Game\IdleRPG\NewRPG\tools\imggen\.venv\Scripts\python.exe" `
  -ArgumentList "server.py" -WorkingDirectory "H:\Game\IdleRPG\NewRPG\tools\imggen" `
  -WindowStyle Hidden `
  -RedirectStandardOutput "...\server.log" -RedirectStandardError "...\server.err.log"
```

> **반드시 분리 실행할 것.** 셸의 배경 작업으로 띄우면 그 작업이 끝날 때 서버도 같이 죽는다.
> 모델 로딩에 약 40초. `server.log`에 `ready on port 8009`가 찍히면 준비 완료.

### 5.3 프롬프트 규칙 (실패를 통해 확정된 것)

1. **부정문은 그 물건을 불러온다.** "NO rope"라고 쓰면 밧줄이 그려진다.
   → 없애고 싶으면 **대체물을 긍정문으로** 묘사한다.
2. **배치를 문장 맨 앞에 둔다.** 배경·스타일을 앞세우면 5칸 배치가 4칸으로 무너진다.
3. **한글을 못 쓴다.** "능력치" → "농먹치". 글자·숫자·아이콘은 **전부 코드로 그린다.**
4. **좌표를 퍼센트로 못박는다.** "from 55 to 77 percent height and 16 to 27 percent width"
   식으로 칸마다 지정해야 배치가 재현된다.
5. **속을 비우려면 명시한다.** 그냥 두면 판때기가 꽉 찬 채로 나온다.
   → "the inside is left completely blank white empty paper, only the contour stroke is inked"
6. **같은 프롬프트 + 같은 시드 = 같은 결과.** 결과가 흔들린다면 프롬프트를 내가 바꾼 것이다.

### 5.4 배경 제거 파이프라인

용도마다 방법이 다르다. **잘못 고르면 그림에 구멍이 뚫린다.**

| 상황 | 방법 |
|---|---|
| 일반 아트 | 마젠타 `#FF00FF` 크로마키 |
| **진홍 계열 아트** | **초록 `#00FF00`** — 붉은 아트는 마젠타와 충돌한다 |
| 먹선만 있는 부품 | **밝기를 알파로 뒤집기** — 안티에일리어싱된 선 끝까지 살아난다 |
| 흰/연분홍 배경 | 모서리에서 **flood-fill** — 전역 판정은 밝은 그림을 갉아먹는다 |

크로마 판정식(현재):
```python
r > 170 and b > 140 and g < 120 and (r - g) > 70 and (b - g) > 50
```
> 옛 판정 `abs(r-255)+g+abs(b-255) < 260`은 **흰색도 통과**해서 연한 수채 그림에 구멍을 냈다.

**주의**: 실측 비율을 쓰는 시트는 배경만 지우고 **잘라내지 않는다.** 자르면 좌표가 어긋난다.

### 5.5 창 아트 제작 절차

1. 코드에서 그 창의 **내용 좌표**를 뽑는다 (탭·격자·버튼이 실제로 놓이는 비율).
2. 그 좌표를 퍼센트로 넣어 통짜 시트를 굽는다 (`scratchpad/gen_wins.py` 형태).
3. 생성된 그림의 **먹선 위치를 픽셀로 실측**한다 (`measure_win.py`).
4. **그림을 기준으로 코드 좌표를 고친다.** 모델은 퍼센트를 대충 따르므로 그림이 정답이다.
5. Unity 메뉴 `IdleMvp/아트/무협 UI 임포트 설정`으로 스프라이트 임포트 설정을 적용한다.

> 임포터는 **자동이 아니다.** 새 파일을 넣은 뒤 메뉴를 직접 실행해야 9-slice 보더가 붙는다.

관련 문서: [wuxia-art-pipeline.md](wuxia-art-pipeline.md), [unity-asset-pipeline-rules.md](unity-asset-pipeline-rules.md)

## 6. 검증 방법

UnityMCP로 에디터를 직접 몬다. 순서를 지키지 않으면 헛검증이 된다.

```
refresh_unity(compile) → read_console(errors) → manage_editor(play)
→ execute_code(C#) → ScreenCapture → 스크린샷 확인
```

**함정**
- 플레이 모드 진입 직후 **첫 캡처는 빈 화면**이다. 한 번 더 찍는다.
- 재컴파일 후 도메인 리로드로 **`Instance` 정적 필드가 날아간다.** 플레이 모드를 껐다 켠다.
- `execute_code`는 CodeDom(C# 6) — 지역 함수·`var` 선언 제약이 있다.
- 에디터가 멈춘 것처럼 보이면 **모달 대화상자**를 의심한다.
  `tasklist /V /FO CSV`로 창 제목을 보면 알 수 있다(임포트 중이 아니라 대기 중).
- 화면 캡처는 **직접 눈으로 확인한다.** 데이터만 보고 "됐다"고 판단하면 놓친다.

### 7.1 코드 · 아트 (이어서 진행 가능)

- 장비창 격자 여백 + 글씨 찌꺼기 정리
- 설정창 버튼을 한지 결로 교체
- 아직 열어보지 않은 모달 전수 점검
  (프리팹에 `WuxWindow` 노드가 없으면 **조용히 건너뛴다** — 설정창이 그래서 혼자 남아 있었다)
- 테마별 배경·발판 전용 아트 (현재 지형 2종·잔도 1종을 색조·두께만 바꿔 공유)
- 무기 세트 보너스 수치 재조정 여부 (소급 적용된 +35%)

### 7.2 유저 작업 영역 (AI가 다루지 않음)

- **키스토어 비밀번호** — AI가 절대 다루지 않는다
- `XAI_API_KEY` — Unity 에디터 프로세스 환경변수로만 읽는다. 스크립트에 적지 않는다
- 에셋 구매·다운로드 승인
- BGM 선정, 실기기 테스트, 플레이 콘솔 등록
